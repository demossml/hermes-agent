## 0. Назначение

Это пакет приёмочных (acceptance) тестов для секретаря Hermes в Telegram.
Человек прогоняет сценарии B1–B6 и регрессионные проверки, фиксирует
результат (PASS / FAIL / SKIP) в разделе 4, затем передаёт этот документ
**ревьюеру (Grok)** для проверки правильности реализации.

> Важно: этот пакет НЕ является автоматическим тест-сьютом. Юнит-тесты
> (`tests/test_secretary_*.py`, `tests/secretary/`) уже покрывают логику;
> B1–B6 проверяют интеграцию «из Telegram» и UX-путь целиком.

## 1. Подготовка

### 1.1 Предусловия

- Запущен gateway (`hermes gateway` или деплой на сервере).
- Есть Telegram-бот, привязанный к секретарю, и тестовый аккаунт-оператор
  (allowlisted в ACL секретаря).
- Чистый контрольный home (или готовность удалить тестовые профили после прогона).

### 1.2 Минимальный корпус — два профиля

| Имя профиля | Назначение | Для чего |
|-------------|-----------|----------|
| `secretary-ceh` | «Цех» (ООО Ромашка) | B1–B6 основной прогон |
| `secretary-hr`  | «Кадры» (ИП Иванов) | проверка изоляции между профилями |

Корпус данных для `secretary-ceh`:
- 2 разовые задачи (`позвонить поставщику @ завтра`, `оплатить счёт`).
- 1 повторяющаяся (`ежедневный отчёт | ежедневно`).
- Умения: `Почта` в `needs_setup` (без реальных IMAP-кредов), `Группы` в `ready`.

## 2. B1–B6 — сценарии

### B1 — Профили: создание, переключение, удаление (L1)

1. В ЛС боту → пикер секретарей → `[➕ Создать]`.
2. Ввести slug `ceh` → должно создать `secretary-ceh` и сделать его активным.
3. Повторить для `hr` → `secretary-hr`.
4. `sec:<profile>` переключение между `secretary-ceh` / `secretary-hr`.
5. Удаление: `sec:delete` → выбрать `secretary-hr` → confirm → профиль исчез.
6. Попытка удалить активный профиль → отказ «сначала переключитесь».

- [ ] PASS / FAIL / SKIP

### B2 — Дерево умений (L2)

1. `/меню → [📋 Что умеет]`.
2. Виден список 6 умений со статусами (`⬜ выкл / ✅ готов / 🟡 настроить / ⚠️ ошибка`).
3. Включить `Задачи` → статус `готов` (без мастера).
4. Выключить `Задачи` → `выкл`.
5. Статус-экран отражает `mail` = `настроить` (нужен мастер).

- [ ] PASS / FAIL / SKIP

### B3 — Мастер настройки + запись в .env (L3)

1. В дереве → `[Вкл]` на `Почта` → открывается мастер `Настройка: Почта (1/3)`.
2. Ввести email → пароль → выбрать провайдера `gmail` (или `other` + хост).
3. Финал → «значения сохранены» + кнопка `[🔍 Проверить]`.
4. Проверить файл: `~/.hermes/profiles/secretary-ceh/.env` содержит
   `SECRETARY_MAIL_EMAIL`, `SECRETARY_MAIL_PASSWORD`, `SECRETARY_MAIL_IMAP_HOST`,
   права `0600`.
5. Повторный вход в мастер → пароль «уже задано» `[Оставить] / [Заменить]`.
6. `[↩ Отмена]` → умение `off`, `awaiting_skill_setup` сброшен.

- [ ] PASS / FAIL / SKIP

### B4 — Валидация умений → ready/error (L4)

1. В дереве на `Почта` → `[Проверить]` (`skill:validate:mail`).
2. С неверным паролем → `⚠️ ошибка` + текст «ошибка входа», кнопка `[🔧 Повторить настройку]`.
3. `[Проверить]` на `Группы` → `✅ готово` (нет внешней проверки).
4. `[Проверить]` на `Зрение` (без `vision-cli`) → `⚠️ ошибка` «не найден».
5. `/secretary_health` → блок «Умения» показывает ready/needs_setup/off/error.

- [ ] PASS / FAIL / SKIP

### B5 — Группы + отчёт «что было» (L5)

1. `/меню → [👥 Группы]`.
2. `[➕ Как добавить]` → инструкция из 4 пунктов.
3. На группе `[Следить]` → чат попадает в allowlist (`archive_admin list_chats`).
4. `[Не следить]` → чат убран из allowlist.
5. `[📊 Что было]` → `[Сутки]` → отчёт приходит в ЛС (сводка: всего/по типу/по чатам), не в группу.
6. Умение `Группы` не ready → экран предлагает `[⚙️ Включить]`.

- [ ] PASS / FAIL / SKIP

### B6 — Задания + расписание (L6)

1. `/меню → [✅ Задачи]` → `[➕ Добавить]` → `позвонить поставщику @ завтра`.
2. Задача в списке «Сейчас» с дедлайном.
3. `[📅 Расписание]` → `[➕ Добавить]` → `ежедневный отчёт | ежедневно`.
4. В расписании: `🔁 ежедневный отчёт — daily (след. …)`.
5. `[✅]` на повторяющейся → `next_run` сдвинут (+1 день).
6. `[🗑]` на повторяющейся → убрана.
7. `[✅]` на разовой → убрана из «Сейчас».

- [ ] PASS / FAIL / SKIP

## 4. Изоляция профилей (ПРОФИЛЬ1 vs ПРОФИЛЬ2)

1. На `secretary-ceh` включить `Задачи` и добавить задачу.
2. Переключиться на `secretary-hr` — дерево умений и список задач **должны быть другими** (не «протекать»).
3. `.env` (`SECRETARY_MAIL_*`) пишется в `~/.hermes/profiles/<name>/.env` — у `hr` нет значений из `ceh`.
